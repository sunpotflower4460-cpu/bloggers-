# input.md — 入力

### C-020 フォームの項目が多い

**よくする**
- 意味のまとまりごとに区切り、段階を分ける
- 今どこにいるかが分かる進行表示を添える

**よくない**
- 全項目を1画面に縦一列で並べる
- 任意項目と必須項目を区別なく並べる

**なぜ**
項目数そのものより、終わりが見えないことが離脱を生む。区切りと進行表示が終わりの見通しを作る。

**型による差**
- 道具型: 段階を分けず、素早く一気に入力させる
- 儀式型: 1段階1項目まで絞り、ゆっくり進ませる
- 遊具型: 入力の完了ごとに小さな反応を返す

**実例**
refs/screens/form-long/

### C-021 数値を入力させる

**よくする**
- 単位を項目のそばに固定表示する
- 想定される範囲や桁数をプレースホルダで示す

**よくない**
- 単位をラベルからだけ推測させる
- 数値専用の入力手段を使わずテキスト入力のままにする

**なぜ**
数値は単位を誤ると意味が反転する。入力の瞬間に単位が見えていないと、誤りに気づく機会がない。

**型による差**
- 道具型: 数値専用キーボードと増減操作で速さを優先する
- 儀式型: 入力そのものより確認の余白を優先する
- 遊具型: 増減操作に触感的な反応を与える

**実例**
refs/screens/form/

### C-022 選択肢が多い

**よくする**
- 検索・絞り込みで選択肢を減らせるようにする
- よく選ばれる選択肢を上位に出す

**よくない**
- すべての選択肢を1つの長いリストのまま出す
- 選択肢をアルファベット順など機械的な順序だけに頼る

**なぜ**
選択肢が多いほど、探す負担がそのまま離脱につながる。並び順と絞り込みが探す負担を代わりに引き受ける。

**型による差**
- 道具型: 検索欄を最上部に固定する
- 儀式型: 選択肢自体を事前に絞り込んだ状態で見せる
- 遊具型: 選択の過程に発見の要素を持たせる

**実例**
refs/screens/select/

### C-023 必須と任意が混在する

**よくする**
- 任意項目にのみ「任意」と明示する
- 任意項目は必須項目より後ろに置く

**よくない**
- 必須項目に「*」だけを付けて説明を省く
- 任意項目を必須項目と同じ強調度で見せる

**なぜ**
「*」の意味は初見のユーザーには自明ではない。任意側に明示する方が、必須側の負担を増やさずに区別できる。

**型による差**
- 道具型: 任意項目は既定で折りたたんでおく
- 儀式型: 任意項目自体を極力持たない設計を優先する
- 遊具型: 任意項目を埋めるほど反応が増える見せ方にする

**実例**
refs/screens/form/
